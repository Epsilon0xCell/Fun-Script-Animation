Storyboard / one shell script / 124 lines

Fun-Script-Animation

A terminal animation: a rocket flies back and forth across a field of 50 stars, bobbing on a sine wave, while the cursor is hidden for the duration of the show.

The board: the script, panel by panel

01Before frame one

The refusal comes first

The script checks for bc before it draws anything, because the sine motion calls bc twice per frame. Without it, both calls fail every frame, the offsets come out empty, and the old behavior was error spam under a rocket that never moves. Now it fails once, up front, with the reason. This panel is a real run on the staging machine, which has no bc installed:

$ bash animation.sh
animation.sh needs bc for the sine-wave motion, and bc was not found in PATH.
exit code: 1. No frame was drawn.
02The set

Fifty stars, placed once

The starfield is placed before the loop and never moves again. Each star gets a position at 1 + RANDOM % width by 1 + RANDOM % height and one character out of ., *, and +, kept for the whole run. The plus 1 matters: terminals number rows and columns from 1, and a position of 0 is invalid. Colors are yellow for the stars, red for the rocket, both stored as literal backslash sequences and interpreted only by the final echo -ne that prints each frame.

03Frame one

The rocket enters at the middle row

Each frame is built in a single buffer and printed with one write, so the terminal never repaints half a frame. In a pty run I captured for this page (with a small stub standing in for the missing bc), the first frame put the rocket at row 12, column 1 of an 80 by 24 terminal, the middle row, moving two columns per frame at about 20 frames per second:

frame 1  cursor to row 12, col 1   [rocket]
frame 2  cursor to row 12, col 3   [rocket]
frame 3  cursor to row 13, col 5   [rocket]
frame 4  cursor to row 13, col 7   [rocket]

The row is recomputed from the middle on every frame instead of added to the last row, so rounding in the sine math cannot drift the rocket away from the center over a long run.

04Short terminal

The wave gets clamped to the screen

The wave amplitude is fixed at 5 rows around the middle. On a terminal shorter than about 11 rows, that math pushes the rocket to row 0 or past the last row, and the position escape for those rows is invalid. Deep Wave 2 proved it with a stub: on an 8-row terminal the old script emitted negative-row escapes in 5 of 6 rocket frames. The fixed script clamps y to the screen, 1 at the top and height at the bottom, and the same test emits 0 bad escapes, with the rocket sitting at row 1. The size itself is guarded too: if tput cannot report one, the script falls back to 80 columns by 24 rows instead of dividing by zero. One limit I left in on purpose: the size is read once at the start, so resizing the window mid-run keeps the old size until you restart the script.

05The bounce

It turns around without leaving

The bounce test uses greater-or-equal and less-or-equal, never equality, because the rocket moves two columns per frame and can step straight past the exact edge column. An equality test would miss the edge on those steps and the rocket would leave the screen. It flips direction at column 1 on the left and at width - 2 on the right, then flies back across the same fixed stars.

06Exit

Ctrl+C gives the cursor back

The cursor is hidden with tput civis only after the restore trap is registered, and the trap sits before the loop: trap "tput cnorm" EXIT. The first version of this script put that line after the infinite loop, where it could never run, so Ctrl+C left the cursor hidden. It is an EXIT trap only, on purpose; trapping INT without exiting would swallow Ctrl+C and the animation would never stop. Stop the show and the stub harness log shows civis at the start and cnorm after the interrupt, which is the proof the cursor comes back.

What this is

I wrote animation.sh as a small terminal show with no ending of its own. There is no story, no score, and nothing to win. A rocket crosses a starfield on a sine wave until I stop it. The whole repo is that one script, 124 lines of bash, plus the banner and logo.

Most of the work in the last two passes was not the picture. It was the edges: a cursor that has to come back, a terminal too short for the wave, a missing bc that should say so once instead of failing twice per frame forever. A toy script is a good place to practice that, because the failure modes are easy to see and the fix is a few lines you can point at.

Run it

$ bash animation.sh
Stop with Ctrl+C. The script restores the cursor on exit.
Needs: a terminal, tput, and bc.
Bash tput (ncurses) bc for sine math ANSI position escapes About 20 frames per second

What was not watched

The campaign verified this script under a stub tput and bc harness and, for this page, I ran it briefly in a pty on the staging machine: the refusal in panel 01 is that run, word for word, and the positions in panel 03 were captured from its output. The campaign did not watch it on a real terminal display, so colors and pacing are as coded, not as seen on a physical screen. I am saying that plainly because a storyboard can make a 124-line script look more finished than it is.
